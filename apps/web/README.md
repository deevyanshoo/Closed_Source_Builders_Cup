# Planning workspace

React Router SPA for the local `/planning` workflow. Start the gateway separately, then run `npm ci` and `npm run dev -- --port 5317 --strictPort` here. Vite listens on `127.0.0.1:5317` and proxies `/v2` to `GATEWAY_URL` (default `http://127.0.0.1:8817`). Set `GATEWAY_DEV_TOKEN_FILE` to the absolute path of the private editor or viewer token file in the Vite process environment. The local development proxy reads it server-side for each request and supplies the Authorization header. Production assets are built separately and served by Go; the build does not read this token file. Never put the token in a `VITE_` variable, tracked configuration, browser storage, or URL.

Run `npm run typecheck`, `npm test`, and `npm run build` before integration. The material catalog, session and plans come from the gateway. Decimal amount fields remain strings across form state and JSON requests. Preview is temporary; a save or revision asks the server to compute a new persisted snapshot. Confirmation reviews every RFQ argument from that saved snapshot. Execution prepares a local draft and shows its persisted receipt, approval history and audit; it never sends an RFQ or places an order. The viewer role disables writes in the UI; the gateway enforces authorization.

The additive session response accepts legacy local `development_only: true` without `identity_mode`, or explicit `identity_mode: development`. A `development_only: false` response requires `identity_mode: private_machine`. That mode identifies an allowlisted service caller, not a signed-in person. Ordinary browsers cannot authenticate with the service token; the UI states that interactive sign-in is unavailable when no session is supplied. Preview remains separate from saved state.
