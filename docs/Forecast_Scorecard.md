# Offline forecast scorecard, version 1

This package scores already frozen monthly prediction rows. It generates no forecasts, reads no database, and makes no provider calls. An exported scorecard is **metric infrastructure only** until the data snapshot and evaluation protocol have been independently accepted. The metadata is supplied by the caller; it is recorded but not verified. In particular, this package cannot establish source publication vintages, training-only calibration, observed-data eligibility, or a leakage-free backtest.

Run from `procurement-engine` with `python3 scripts/evaluate_forecasts.py --input INPUT.json --output-dir NEW_RUN_DIR`. The destination must not exist. The command writes `predictions.json` as a byte-identical, read-only copy, `metrics.csv`, `manifest.json`, and `report.md`. The manifest records the input byte count and SHA-256, the scoring configuration hash, module and CLI hashes, row count, and caller metadata. It does not certify the metadata's truth. A failed validation leaves the output path untouched; an existing run is never overwritten.

`RUN_STATE.json` distinguishes an incomplete directory from a published run. The program creates the directory exclusively, writes `status: incomplete` before artifacts, and atomically replaces that state with `status: complete` only after all four artifacts exist; the complete state contains each artifact's SHA-256. A reader must require the complete state and verify those hashes before treating the directory as a run. A process interruption or ordinary write failure may leave an incomplete directory, which is preserved for inspection. Retrying the same destination refuses to overwrite it; retry with a new output path. An unrelated competing destination is never deleted or overwritten. A termination during the tiny interval after directory creation but before the first state write leaves no state file and must also be treated as incomplete. This is a process-interruption protocol, not a promise of cleanup after `SIGKILL` or power loss.

The input is a JSON object with exactly `schema_version: "forecast-scorecard.v1"`, a `metadata` object, and a `predictions` list. Duplicate JSON keys and `NaN`/`Infinity` constants are rejected. Each prediction has exactly these fields:

`series_kind` (`commodity`, `fx`, or `joined`), `series_id`, `unit`, `source_id`, `is_synthetic` (boolean), `split` (`validation` or `test`), `origin` and `target` (`YYYY-MM`), positive integer `horizon`, `model`, `backend`, `training_cutoff` (`YYYY-MM`), finite numeric `p0`, `p10`, `p50`, `p90`, `actual`, and finite nonnegative numeric or null `mase_scale`. Text identity fields must be nonempty. Prices may be negative. Quantiles must be ordered, target must equal origin plus horizon, and cutoff cannot follow origin. A cutoff date alone does not prove that each training observation was published by that date.

The prediction identity is kind, series, split, origin, target, horizon, model, backend. It must be unique. Rows sharing kind, series, split, origin, target, horizon must agree on unit, source, synthetic flag, actual, p0, supplied scale, and cutoff. More than one `naive` backend for a cell is ambiguous and rejected. Metrics group kind, series, unit, source, synthetic status, split, model, backend, horizon; commodity, FX, joined, synthetic, observed, validation, and test scores cannot pool.

Point error is based on P50. MAE and RMSE remain in the original unit. MASE averages each absolute error divided by its caller-supplied, training-only scale; null or zero scales are counted as undefined. Pinball loss uses P10/P50/P90. P10–P90 coverage is inclusive, with nominal 80% coverage and mean interval width. Directional hit rate requires both actual and P50 to move strictly above or below p0; actual no-change, prediction abstentions, and eligible count are shown. A row can count in both no-change and abstention. Arithmetic uses decimal intermediates so a representable RMSE such as `1e200` does not overflow while squaring. If a final metric cannot be represented as a finite JSON number, its value is `null` and the corresponding reason is `numeric_overflow`; cells remain counted. No value is clipped, dropped, or silently changed. No universal accuracy percentage is reported.

For each non-naive test group, skill compares model and naive P50 absolute errors on identical cells only: `1 - model_matched_MAE / naive_matched_MAE`. The CSV reports matched and missing cells and both matched MAEs. Skill is undefined when no naive cell matches or naive matched MAE is zero. Validation groups and naive groups have no skill. The seeded moving-block bootstrap resamples paired per-origin absolute-error reductions (`naive error - model error`) in chronological blocks of six monthly origins. It needs at least two blocks (12 origins), otherwise its interval is explicitly undefined. Replicate count is 100–10,000, default 1,000; seed is an unsigned 32-bit integer. The bootstrap interval is for absolute-error reduction in original units, not for skill. Overlapping forecast targets, correlated origins, small samples, and unavailable historical publication vintages limit its interpretation.

Observed-data readiness, freeze of raw inputs, forecast generation, model selection/calibration at each origin, charts, and procurement-policy value remain separate later tickets. An actual observed accuracy claim requires an accepted source snapshot and protocol, held-out test predictions, and independent review of leakage and provenance.

Human-readable table labels are HTML escaped, pipe encoded, and line/control characters rendered as visible `\uXXXX` text. Raw input bytes and CSV data retain the caller's original labels.
