# Voice architecture for the manufacturing sourcing demo

Research checked against vendor documentation on 6 October 2026. This is an architecture recommendation for a two-person, 12-day build; no service was provisioned or benchmarked.

## Recommendation

Use a **text-first Google Cloud stack**: browser microphone → small backend → Cloud Speech-to-Text V2 `chirp_3` streaming → visible, final user transcript → Gemini text reasoning through Google Cloud/Vertex AI credentials over cited sourcing evidence → validated answer/decision card → Cloud Text-to-Speech streaming with a Chirp 3 HD voice. Make the first demo push-to-talk and one turn at a time. Add interruption by stopping local playback, canceling/ignoring the old TTS stream, and opening a new recognition turn. This preserves a reviewable transcript and makes approval before a consequential tool action straightforward. The backend owns credentials and the evidence/action log. Chirp 3 supports `StreamingRecognize`, and Google documents bidirectional TTS streaming for Chirp 3 HD voices; that TTS path is **Preview**. Use ordinary nonstreaming Cloud TTS as the fallback if Preview streaming is unavailable; do not build a second full voice stack. [Chirp 3 transcription](https://docs.cloud.google.com/speech-to-text/docs/models/chirp-3) · [Cloud TTS streaming](https://docs.cloud.google.com/text-to-speech/docs/create-audio-text-streaming) · [Cloud TTS synchronous API](https://docs.cloud.google.com/text-to-speech/docs/reference/rest/v1/text/synthesize) · [Google Cloud Gemini setup](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/start)

This is an engineering judgment, not a vendor claim. The chain has more integration points than Gemini Live and likely adds turn latency, but a sourcing assistant's differentiator is showing *which supplier quote, currency, date, and assumption* produced a number. A full-duplex voice experience is less valuable than a defensible first result in this schedule. Keep typed input and silent text output as a demo fallback if microphone or speech APIs fail.

## Conversation and evidence contract

1. Treat interim recognition as display-only. Commit a user turn only on a final transcript. Let ordinary read-only supplier comparisons proceed directly, with the final transcript visible and editable. Pause for confirmation only when a critical field is ambiguous or before a committed write. Chirp 3's documented streaming sample checks `is_final`; its `endpointing_sensitivity` trades speed for the risk of cutting off a pause. Use `STANDARD` initially, then test `SHORT` on short commands. Do not assume word-level confidence: Google's Chirp 3 page says the returned word-confidence value is **not** a true confidence score, and streaming word-level timestamps are not supported. [Chirp 3 features and endpointing](https://docs.cloud.google.com/speech-to-text/docs/models/chirp-3)
2. Store each turn as `{turn_id, final_transcript, edited_transcript, cited_source_ids, source_snapshot_time, proposed_action, approval_state, result}`. For each number, show original value, unit, currency, quote date, source, conversion rate/source/date if converted, and calculation. These fields and validations are application requirements, not speech-model guarantees. Gemini structured output can enforce JSON shape but Google warns it does **not** guarantee semantic correctness; validate arithmetic, allowed currencies, source IDs, and freshness in application code. [Gemini structured outputs](https://ai.google.dev/gemini-api/docs/generate-content/structured-output)
3. Require an explicit confirmation card when a consequential digit, decimal, unit, currency, or supplier ID is ambiguous, and for any committed write. Read back the normalized value in the UI and, where useful, in speech: “₹12.5 lakh per tonne, dated 5 October — confirm?” Do not submit a purchase order, message a supplier, mutate a quote, or change a project record merely because a model requested a tool. Google documents that function calls are executed by the application, not automatically by the model; the approval gate is our design. [Gemini function calling](https://ai.google.dev/gemini-api/docs/function-calling)
4. On user speech or a Stop control during TTS, immediately stop playback and discard queued chunks. Mark the old `turn_id` canceled and ignore late model/TTS responses. Gemini Live offers server-side interruption signals and canceled pending calls if that route is later adopted, but its docs still require clearing the client audio buffer. [Live interruption behavior](https://ai.google.dev/gemini-api/docs/live-api/capabilities) · [Live best practices](https://ai.google.dev/gemini-api/docs/live-api/best-practices)

## Build order and unresolved checks

These are **targets, not measured completion**:

- **7 October:** typed sourcing tools return cited evidence and validated numbers; run a speech quota, region, and quality spike with sample commands. Chirp 3 offers phrase biasing, but accuracy for this vocabulary is unmeasured here. [Chirp 3 model](https://docs.cloud.google.com/speech-to-text/docs/models/chirp-3)
- **8 October:** integrate push-to-talk STT → tools → TTS, with final transcript visible and ordinary nonstreaming Cloud TTS available if the Preview streaming path is unavailable. [Cloud TTS streaming](https://docs.cloud.google.com/text-to-speech/docs/create-audio-text-streaming) · [Cloud TTS synchronous API](https://docs.cloud.google.com/text-to-speech/docs/reference/rest/v1/text/synthesize)
- **9 October:** stream responses, handle interruption and reconnect, and measure end-to-end latency and recognition on representative commands; guard against stale turns.
- **10–13 October:** refine sourcing evidence, critical-field confirmation, errors, UI, and rehearsed cases: correct value, misheard currency, stale quote, no cited source, interruption, and explicit action rejection. Do not split effort into another full voice stack.

Verify service availability, quotas, region, price, microphone permissions, and real latency in the team's own project before committing the final demo. Google's current Chirp 3 page lists `us` and `eu` multiregions as GA and says to query its locations API for latest availability. Its TTS streaming guide requires a billed, API-enabled Cloud project. [Chirp 3 availability](https://docs.cloud.google.com/speech-to-text/docs/models/chirp-3) · [Cloud TTS setup](https://docs.cloud.google.com/text-to-speech/docs/create-audio-text-streaming)

## Credit and account caveat

Google's Free Trial offers eligible new customers **$300 for 90 days** on covered Google Cloud services and does not bill during the trial; the offer has eligibility and feature restrictions. The recommended Gemini reasoning route uses **Google Cloud project credentials** through Gemini Enterprise Agent Platform/Vertex AI, for which Google recommends Application Default Credentials. The trial credit **cannot pay for Gemini API in AI Studio costs**; that is the separate Gemini Developer API route and should not be confused with the chosen Cloud route. Do not assume a trial covers every model, SKU, region, or a Fish Audio account. Check the account's actual billing state, selected model/SKU pricing, and quotas before enabling services; no current account balance or contest-specific credit was verified in this research.
