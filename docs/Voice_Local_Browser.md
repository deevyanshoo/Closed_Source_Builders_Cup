# Local typed scenario workspace

`/scenarios` is an authenticated, read-only synthetic comparison workspace. It uses the existing loopback development-session transport, the local HTTP lifecycle, and the fixed Python recovery tool. It does not use speech, a model, SQL, a saved plan, or a supplier action. Typed inputs are explicit scenario arguments, never a transcript.

The host provides the existing same-origin proxy and private local identity file. The page never asks for, embeds or persists a bearer token or API key. Configure the existing gateway and frontend transport as documented in the platform setup; opt into the fixed executor using the existing `-voice-local-python` and `-voice-local-source` host flags. No new authentication bypass exists. Private-machine/production interactive authentication remains outside this increment.

Select a complete supplied synthetic example, review its stock, component quantities, resources, production periods and UTC dates, then edit receipt arrivals and complete order assignments. Create a session from the immutable supplied snapshot and run a comparison. The server issues context and scenario identity; the client adapts the request to that scenario and verifies returned ownership before rendering the public numerical output. Decimal quantities and durations remain strings. Modeled material, capacity and due-date checks are separate and do not establish full production feasibility.

Cancel removes displayed results and explicitly cancels known accepted work. Replacement closes the preceding session and creates a fresh one, keeping uncertain old starts separate from new work. Changes to inputs or authenticated identity invalidate prior results and close known context. Late responses cannot become current. Polling and request waiting are bounded; POST writes are never automatically retried. An aborted HTTP request alone cannot prove that server-accepted work stopped. If a creation response is lost before its session ID is received, that unknown session can remain until the existing server idle expiry. Cleanup failures remain visible rather than proving a cancelled operation. Foreign or expired identifiers fail closed. The server deliberately uses the same 404 for both: after an identity change the new caller cannot prove closure of old-owner resources. The client hides them and attempts cleanup without retaining old credentials; inaccessible resources rely on existing server idle expiry.

Authentication is checked before use, on explicit refresh/window focus, and before accepting a completed result. Checking identity hides preceding results; an external host identity change is observable only on the next request. Page refresh loses process-local browser state and requires a new session. Nothing is restored from localStorage.

Unavailable configuration, capacity, expiry, invalid input, unsupported numerical scope, clarification, rejection and execution failure are distinct visible states. This page does not silently reinterpret unsupported units, calculate a substitute outcome, or apply a plan.

## Verification boundaries

Focused fake-timing client/component tests support browser request ownership claims. Mounted production-browser checks support actual rendered lifecycle behavior. Four separate connected production React -> existing authenticated Go -> fixed Python -> poll cases compare the returned outcome exactly with the independent public recovery tool, including high-precision quantity strings. Synthetic expiry/capacity/timing fixtures demonstrate client presentation only; they do not establish provider behavior or operational truth. Exact acceptance receipts and desktop/mobile captures are recorded in `outputs/Voice_Local_Browser_Report.md` in the coordinator workspace.

This prerequisite does not complete issues 2 or 4, production identity, microphone/STT/model/TTS, speech latency, deployment or persistent-plan freshness. The global provider pilot remains exhausted and SQL activation remains held. Root owns integration and all provider/account actions.
