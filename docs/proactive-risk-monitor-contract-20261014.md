# Proactive risk extension: approved execution scope
User requests automatic relevant-news, supplier-delay and inventory risk flags across all ten fictional companies, impact explanations and recovery suggestions. Implement within existing hosted demo; coordinator deploys. No real messages/orders, IAM/billing/private data, scheduler or new infrastructure. Existing link and company-isolated session workflows preserved. Monitoring occurs automatically on opening and every 60 seconds while visible; news uses existing 15-minute cache. No paid model calls during automatic scans. Google agent/voice can read the report and prepare reviewed actions on user request.

## Shared wire contract (coordinator owns server routes)
GET /api/demo/risks (authenticated existing session), no request body. Response:
{company_id: current active company, context_version: current version, checked_at: ISO UTC, monitoring: "while_workspace_open", news_refresh_seconds:900, companies:[CompanyRiskReport exactly ten], summary:{high:number,medium:number,low:number,companies_with_alerts:number},limitations:string[]}
CompanyRiskReport:
{company_id:string,company_name:string,sector:string,checked_at:string,alerts:RiskAlert[],coverage:{materials_evaluated:number,news_state:string,news_items_evaluated:number,sources:SourceState[]},data_gaps:string[]}
RiskAlert:
{alert_id:string(stable deterministic hash),company_id:string,category:"inventory"|"supplier_delay"|"news",severity:"high"|"medium"|"low",title:string,summary:string,impact:string,material_ids:string[],provenance:"synthetic_profile"|"synthetic_plan"|"synthetic_delay_scenario"|"observed_news",confidence:{level:"high"|"moderate"|"low",reason:string},evidence:[{kind:"profile"|"order"|"plan"|"news",ref_id:string,label:string,detail:string,url:string|null,observed_at:string|null}],metrics:Record<string,string|number|null>,recovery_actions:[{action_id:string,label:string,message:string,requires_review:boolean}]}
Count severities from returned alerts; stable per-source/category dedup; bounded <=60 alerts/company and <=5 news alerts/company; all catalogue materials evaluated. No raw source HTML or private documents. Reports are session-bound; preserve all current plan/form edits when polling and never auto-switch company or mutate quotes/proposals. Stale asynchronous report response cannot populate another company/context/session. Provider news failures explicit; retain deterministic inventory/order checks.

## Backend engine worker contract
Create pure assess_company(snapshot:dict,news:dict|None,now:datetime)->CompanyRiskReport in procure.demo.proactive_risks. Snapshot {company_id,company:trusted catalogue,offers:list,last_plan/plan,plan_request,recovery,buyer_draft,selected_material_id}; empty unswitched company uses catalogue and no plan. Do not mutate input. Only owned-company/material/saved/version-bound plan evidence; reject foreign/bad facts. Decimal units never aggregate unlike materials. Inventory per material cover=stock/daily, gap if cover <= shortest listed supplier lead; explicit buyer stock override is a synthetic assumption for matching unit/material only. Supplier category: dated order need-by vs as_of + material supplier lead; distinguish potential late arrival under synthetic assumptions from confirmed delay. Current recovery uses validated recorded delay_days_by_offer and scenario/baseline plan; explain selection change/infeasible/current alternatives, never claim real shipment delay. Use company as_of/scenario decision dates, not advancing synthetic dates with real calendar. News: mapped direct/sector/route/currency only, owned materials/routes/currencies; refuse unmatched/future/stale >7day headline/retrieval metadata and source stale/unavailable. Source reliability separate from recommendation confidence. Headline match implies conditional exposure, never confirms delay or price move. Relevant risk/disruption headlines prioritized, max5; routine sector matches can be low-priority watch signals. Evidence includes public URL/id and observed timestamp. Missing inputs/gaps explicit. Alert impact explains potential stockout/order/supplier or conditional news outcome. Recovery_actions are safe short messages with exact material names/IDs for existing text operator: inventory inspect/load quote alternatives, supplier recovery only existing plan/explicit delays, news explain, simulated email or unsent RFQ with prerequisites. Do not invent lead time delta or direct-send action.
